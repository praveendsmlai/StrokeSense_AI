## TASK 3 — REAL MEETING MINUTES GENERATION

Update the existing endpoint:

`POST /api/v1/connects/{connect_id}/generate-minutes`

The endpoint must:

1. Authenticate the user and enforce role and IBU authorization.
2. Verify that the Connect exists in Arun's SQL Server lifecycle tables.
3. Read the authorized Connect context, available evidence, and metadata.
4. Support transcript and manual-note input according to the existing API contract and PRD.
5. Retrieve already uploaded evidence through existing storage references where applicable.
6. Treat transcript and other user-provided material as untrusted input, not executable instructions.
7. Validate input size, required evidence, and supported content types.
8. Send the appropriate sanitized and authorized input to Azure OpenAI.
9. Generate meaningful, structured meeting minutes grounded only in the provided meeting evidence.
10. Preserve discussion points, decisions, owners, follow-ups, and unresolved concerns.
11. Avoid hallucinating attendees, decisions, dates, or commitments.
12. Validate the structured model output before database persistence.
13. Store generated output in `connect_minutes` with `DRAFT` status.
14. Record provider and audit metadata where available.
15. Return the existing API response contract, extending it only where necessary and backward-compatible.

**Never automatically publish generated minutes.**

A human reviewer must explicitly validate and approve the draft before publication.

If Azure OpenAI is not configured, return a clear controlled provider-unavailable response. Do not create fake AI minutes or report AI generation as successful.

- Source evidence

Persist extracted action candidates according to the PRD's human-validation workflow, keeping them pending review rather than immediately activating unapproved actions.

Prevent accidental duplication on retries or repeated extraction.

Use `connect_actions` and relevant Praveen-owned structures without modifying Arun's tables.

Do not mark extraction as successful when no provider call took place.

Preserve the distinction between:

- Provider execution success
- Zero genuine actions extracted
- Actions pending human review
- Provider unavailable
- Extraction failed
