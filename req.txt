# PEOPLECONNECT — PHASE 4: AZURE COMMUNICATION SERVICES INTEGRATION

Implement production-oriented email notification functionality using Azure Communication Services (ACS).

## Mandatory Rules
- Work ONLY on Praveen's assigned Module 3 and notification-related tasks.
- DO NOT modify Arun's lifecycle code or database tables.
- Preserve existing MS SQL Server tables and data.
- Use existing database models and APIs wherever possible.
- Use `py -m` instead of `python` on Tech Mahindra Windows.
- Use existing `requirements-lock.txt` for dependencies.
- Do not introduce mock email delivery into production.
- Do not claim successful delivery without provider confirmation.
- Preserve JWT authentication, RBAC and IBU-based access controls.

## Requirements

### 1. ACS Integration
Implement a real Azure Communication Services email provider.

Support:
- ACS connection string authentication.
- Microsoft Entra ID authentication where supported.
- Configurable sender email address.
- Environment-based configuration.
- Secure credential handling.

### 2. Email Notifications
Implement and integrate notifications for:
- Published meeting minutes.
- Action item assignment.
- Action status updates where required.
- Upcoming action due dates.
- Overdue actions.
- SLA breaches.
- Escalations.

### 3. Email Templates
Create configurable templates containing relevant Connect details, action owner, due date, status and escalation information.

### 4. Reminder Automation
Implement scheduled reminder processing based on existing SLA and escalation rules.

Prevent duplicate notifications using idempotency keys.

### 5. Delivery Tracking
Track:
- Notification ID
- Recipient
- Notification type
- Provider message ID
- Delivery status
- Retry count
- Error details
- Created and sent timestamps

Use existing notification tables where compatible. Do not create duplicate tables unnecessarily.

### 6. API Integration
Inspect existing notification APIs first.

Reuse or extend them only where functionality is missing. Preserve existing API contracts unless changes are necessary and documented.

### 7. Error Handling
Handle missing ACS credentials, authentication failures, timeouts, throttling and delivery failures.

Never mark an email as SENT unless ACS confirms acceptance. Track delivery confirmation separately.

### 8. Testing
Perform offline tests using controlled provider mocks.

Verify:
- API authentication and authorization.
- Email payload generation.
- Retry behaviour.
- Reminder scheduling.
- Duplicate prevention.
- Delivery status persistence.
- Existing backend regression tests.

Live ACS testing can remain pending until Tech Mahindra provides credentials.
